# Easy Data × AI 共学笔记｜第 5 篇｜从 Agent 记忆到用 SQL 查工作记录

这是我在 Datawhale 上参与的 Easy Data × AI 共学项目的学习笔记，今天是 11 月 28 日，这是我的第 5 篇。

这次是 **Task 5**，学的是产品篇 **P3《Agent 记忆系统设计》**和产业应用篇 **I4《File SQL for AI Agent》**。

> **说明**：我的每次学习笔记，正文都是根据我课后的学习口述内容，用 AI 整理而成的。口述里的观点和经历都是我自己的，AI 只负责把口语整理成文字。

### 从「龙虾」记不住，想到把线程保存下来

年初用「龙虾」的时候，它经常记不住前面说过的事，给我留下了挺深的坏印象。后来我就想了个办法，每次退出一个线程，让它把这次对话保存下来。这个办法比较笨，但下次接着做，至少有东西可翻。

现在我每天晚上收工，会在各个 Agent 里手工触发一次「同步保存」。把当天的线程按时间归档到工作区和 Obsidian，主机和笔记本都做，再用笔记本上的 Codex 汇总。工作记录用 Markdown 保存，文件名带日期和 Agent 名称。这里面有我的思考、做出来的东西，还有事情怎么推进、问题怎么解决。我看重记忆，就是因为这些过程也是自己的工作资产。

P3 讲到，Agent 可以在对话中判断什么值得记，也可以等对话结束后再提炼。我让 Agent 帮忙查了本机的 Codex 桌面版，发现本地记忆已经开启。它会从符合条件的对话里提炼摘要，供以后接续。这样我有两份用途不同的东西：原始工作记录留给自己回查，提炼的摘要帮助 Agent 接上手。

### 记得住之后，还得找得到

以前按日期和 Agent 存文档，知道哪天谁做了什么，翻起来没问题。但如果我只记得遇到过一个报错，忘了是哪天、在哪个 Agent 做的，光靠日期就不够了。

我请 Agent 从 23 份 Obsidian 工作日志里选了 10 道我可能真会回查的问题。用同样的问题，分别按日志文件搜和按项目短条目搜。正确原文排第一的题，从 **6 道变成了 8 道**。但两种搜法在前三条里都只找到 **8 道**，程序查询时间也没变快。这组小样至少让我看见，整理得短一些可以改善排序，但也可能漏掉别的内容。

后来我们做了一份项目索引，收了 21 条决策、验收和排障结论，每条带日期和原文链接。上次漏掉的两题，一题是某阶段的打卡截止时间，一题是某个仪表盘变更的提交号，复测都能在第一条找到。那两题在做索引以前已经知道，所以这次只能说明这份索引对已收录的内容管用。现在我让「同步保存」顺手更新索引，只有新结论或者旧结论确实发生变化才补一条，细节仍然可以点回原文。

P3 的艾宾浩斯遗忘曲线我也很感兴趣。查下来，课程提到的 PowerMem 确实做过随时间降低记忆权重的机制，它的后继项目叫 PowerContext。我眼下更想先让自己的记录好找一点，所以暂时不装。比如一句「我今天赶时间」，过几天可以不再优先想起来。一次排障的解决过程，就算半年没用，我也希望找它的时候还在。

### I4 看不懂，我拿自己的索引试了一次

I4 刚看时，我连 File SQL 是什么都没弄懂。我还问，它跟 MySQL 有什么区别，是不是一个存数据、一个存文件？

用自己的资料跑了一次就好理解了。我们把项目索引导成 CSV，每行有项目、日期、类型、标题、结论和原文位置。然后我问 Agent：「每个项目有几条排障记录？」它用电脑上已有的 Microsoft ACE 文本驱动，直接对 CSV 执行 SQL。SQL 按项目分组，把类型是「排障」的记为 1，其余记为 0，再把每组加起来。这样没有排障记录的项目也能显示。

这份 CSV 一共 **21 条记录、11 个项目**。查询结果是 **4 个项目各有 1 条排障记录，其余 7 个项目是 0 条**，逐行核对也一致。这个结果说的是我收进索引的记录数量。

这次我终于能把 File SQL 和前面学的东西区分开了。我要找「那次报错后来怎么解决」，可以按关键词或意思找原文。我要问「每个项目有几条排障记录」，只要手头已经有一份列名清楚的 CSV，就可以对着文件筛选、分组、计数。这次 SQL 的数据来源就是那个文件，中间没有先建表再导入。以后收到临时导出的表格，要统计或对账，我就知道可以先让 Agent 看列名，再做一次小范围查询。
